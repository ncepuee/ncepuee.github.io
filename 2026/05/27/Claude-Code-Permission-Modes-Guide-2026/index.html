Claude Code 权限模式详解：5 种模式与 settings.json 配置指南

发表于 2026-05-27 分类于 效率工具

一、前言

使用 Claude Code 时，每次执行命令、编辑文件或调用工具都会弹出权限确认，这在日常开发中略显繁琐。特别是当你明确知道当前操作是安全时，反复确认很打断思路。

Claude Code 提供了一套灵活的权限系统，包含 5 种模式，支持从「完全弹窗」到「完全放行」的梯度控制。本文详细介绍每种模式的用法和配置方式。

另外，如果你在恢复（resume）一个已有会话时想跳过权限确认，可以使用：

这就是你之前使用过的命令格式，后面会详细说明。

二、Claude Code 的 5 种权限模式

Claude Code 按权限从严格到宽松分为 5 种模式：

模式 文件编辑 Shell 命令 MCP 工具 适用场景
Default（默认） 每类弹窗一次 每次弹窗 每次弹窗 新用户、不熟悉的项目
Accept Edits（接受编辑） 自动批准 每次弹窗 每次弹窗 日常开发
Plan Mode（计划模式） 禁止 禁止 禁止 代码审查、方案分析
Don’t Ask（别问） 拒绝 拒绝 拒绝 锁定环境、只读审查
Bypass（跳过/YOLO） 自动批准 自动批准 自动批准 CI/CD、可信环境

前三种模式可以通过快捷键 Shift+Tab 在会话中循环切换。

注意：--dangerously-skip-permissions 没有短别名（比如没有 -y），目的就是让你每次使用时都意识到这是高风险操作。它相当于把整个文件系统的写入权限和命令执行权限全部交给了 AI。

何时使用：

  • CI/CD 流水线中的自动化任务
  • Docker 等沙箱环境中的操作
  • 你完全了解当前会话的上下文，且项目有版本控制可以回退
  • 长时间会话中频繁确认影响效率

何时不要使用：

  • 生产环境
  • 包含敏感文件（.env、密钥等）的项目
  • 不熟悉的代码库
  • 需要审计操作记录的场景

四、通过 settings.json 精细控制（推荐）

如果你觉得跳过所有权限太激进，又不想每次手动确认，可以使用 .claude/settings.json 进行精细化权限配置。

4.1 配置文件位置

  • 项目级配置：项目根目录/.claude/settings.json（推荐）
  • 用户级配置：~/.claude/settings.json
  • 本地覆盖：.claude/settings.local.json（自动生成，用户手动批准的规则写在这里）

4.2 三级规则：allow / deny / ask

规则优先级（重要）：
deny > ask > allow

第一条匹配的规则生效。如果一条命令同时匹配了 allow 和 deny，deny 优先。

4.3 设置默认权限模式

可选值："default" / "acceptEdits" / "plan" / "bypassPermissions"

4.4 模式说明

规则 作用
allow 匹配的操作自动批准，不弹窗
deny 匹配的操作直接拒绝，不弹窗
ask 匹配的操作仍然弹窗确认（覆盖 allow）

4.5 模式语法

  • Tool：Bash、Read、Edit、Write、WebFetch、WebSearch、Grep、Glob 等
  • pattern：glob 通配符，支持 * 和 **

六、VSCode 扩展中的注意事项

VSCode 扩展的权限配置与 CLI 有所不同。要在 VSCode 中启用 Bypass 模式，需要配置两个地方：

  1. 在 VSCode 设置中开启：claudeCode.allowDangerouslySkipPermissions: true
  2. 设置初始权限模式：claudeCode.initialPermissionMode: "bypassPermissions"

已知问题：VSCode 扩展中 allow: ["*"] 和 defaultMode: "bypassPermissions" 的设置在扩展中经常被忽略，不如 CLI 可靠。如果遇到权限问题，建议切换到 CLI 使用。
