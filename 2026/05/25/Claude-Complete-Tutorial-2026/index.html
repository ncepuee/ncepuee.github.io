发表于 2026-05-25 分类于 AI工具

前言

Claude Code（简称 cc），是 Anthropic 在 2025 年 2 月推出的终端 AI Agent 程序。它最初为编程而生，但现在能做的远远不止编程——文案撰写、数据分析、资料整理、内容创作，几乎任何知识工作都能胜任。

与普通对话式 AI 不同，Claude Code 具有更高的自主性：它会自己制定计划、调用工具、观察结果并决定下一步行动，循环往复直到任务完成。这个机制被称为 LLM Loop。

本文将带你从安装配置到高级扩展，一步步掌握 Claude Code。

一、Claude Code 是什么

1.1 与对话式 AI 的本质区别

传统对话 AI 采用一问一答的模式，而 Claude Code 要自主得多：

  • 它自己制定计划
  • 自主调用工具（读文件、执行命令、下载资源）
  • 观察结果并决定下一步
  • 循环往复直到任务完成

1.2 Claude Code 的两大优势

本地运行：在有限权限下可以直接读写本地文件、使用终端、执行命令。数据不出本地，安全可控。

Harness 工程：Harness 是大模型之外让 Agent 表现更好的工程设计。同样的大模型，不同的 Harness 效果天差地别，而 cc 是 Harness 的集大成者。

1.3 它能为你做什么

  • 开发应用：即使没有编程基础，也能做出真正可用的应用
  • 内容创作：写文案、查资料、文稿分析、素材匹配
  • 数据处理：整理数据、做表格、写报告
  • 办公自动化：法律、财务、市场等各类知识工作

二、安装与配置

2.1 安装方式

最原生、功能最全的方式是终端模式，配合一个 Agent IDE（如 Cursor）使用体验最佳。

方式一：一行命令安装

从 Claude Code 官网 复制安装命令，在 IDE 终端执行。安装后输入 claude --version 验证版本号。

方式二：让 Agent 帮你安装

更 AI 原生的方式：告诉 IDE「帮我安装 node 并用 npm 安装最新的 claude code」，它会自动完成，包括处理依赖和网络问题。

2.2 配置大模型：CC Switch

Claude Code 的「大脑」可以自由选择。推荐使用 CC Switch 管理多模型切换：

下载地址：https://github.com/farion1231/cc-switch/releases

填入 API Key 和 Base URL 即可。可以配置多组 Key，随意切换档位。

⚠️ 注意：操作 CC Switch 必须在启动 cc 之前，否则会默认走登录流程。很多新手在这儿翻车。

2.3 首次启动

依次完成初始设置：主题色 → 安全确认 → 推荐设置 → 确认文件夹可信，一般全部回车通过即可。

三、三种权限模式

cc 通过 Shift+Tab 循环切换三种模式：

模式 行为特点
Plan Mode（计划模式） 先出详细计划，等你确认后才动手
默认模式 自动判断哪些要问你、哪些直接做
Accept Edits 改文件不询问，执行命令仍需同意

另外还有一个极速模式（全程绿灯不询问）：

Anthropic 发现 97% 的情况下用户都会直接同意。新手建议从默认模式开始。

四、第一个项目：桌面番茄钟

4.1 开始对话

启动后直接对它说：

「帮我做一个桌面番茄钟软件」

它不会直接动手——指令模糊时会主动提问确认技术栈。这是 cc 的特点：上下文不清楚时主动追问。

4.2 计划与执行

选择技术栈后进入 Plan Mode，先给出详尽计划。确认后开始创建代码。安装依赖时会询问权限，选择「同意，并且以后不再询问」最方便。

4.3 运行项目

项目装好后，两种方式运行：

  1. 新开一个终端运行命令
  2. 在 cc 对话中使用 ! 进入 bash 模式直接运行

运行后输入 Ctrl+B 让它在后台运行，不影响继续对话。

五、日常交互技巧

5.1 @ 文件引用

明确 @ 一个文件可以提高效率、省 token。cc 不会一直加载所有项目文件，通常通过 grep 找文件。明确引用能帮它快速定位。

💡 提示词太长不方便在终端输入时，先建一个文档写详细要求，再 @ 这个文档。

5.2 多模态输入

直接拖拽图片或粘贴到对话框，利用多模态能力让 cc 理解视觉内容。比如给一个配色参考让它调整应用主题。

5.3 斜杠命令速查

命令 作用
/help 查看所有命令
/model 切换高中低档模型
/btw 顺便问一句，不污染主上下文
/compact 压缩上下文，释放 Token 空间
/clear 彻底清空，重开对话
/resume 恢复之前的对话
/init 初始化项目，生成 CLAUDE.md
/context 查看上下文占比详情
/simplify 派生 3 个 Agent 做代码审核优化
/agent 手动创建子 Agent
/plugin 插件管理
/memory 记忆管理

换行技巧：Mac = Option+Enter，Windows = Ctrl+Enter。⚠️ Shift+Enter 是直接发送，很多人在这儿发送了半截提示词。

💡 冷知识：给 cc 的指令越短，它花费的 token 可能越多——指令不足时会花更多 token 去探索本地文件。描述越具体，效果越准确。

六、后悔药与上下文管理

6.1 快速撤回

双击 ESC 或输入 /rewind 进入回滚界面，可选：

  • 仅回滚对话
  • 回滚对话和编辑过的文件
  • 只回滚文件

局限：只能撤 cc 自己编辑的文件，终端命令（安装包、下载）撤不了。

6.2 Git：真正的后悔药

把 Git 理解为「游戏的存档系统」——每完成一个阶段性工作就让 cc 存一次档，翻车了就读档回来。

cc 可以用自然语言帮你完成全部 Git 操作。建议养成习惯：每做完一步就让 cc 存档一步。有 Git 兜底，也更放心让 cc 去尝试各种方案。

6.3 上下文管理

所有 AI 都面临的问题——上下文窗口有限。cc 的 1M 上下文看着大，实际有效比例 60%-80%，且随上下文增多能力下降。

核心命令：

命令 作用
/compact 主动压缩上下文，保留关键信息释放空间
/clear 彻底清空，重开对话
/context 查看详细 Token 占用情况

建议打开底部实时百分比显示，上下文高于 60% 就 /compact 一下。

七、让 cc 记住你是谁：三层记忆体系

7.1 CLAUDE.md——第一优先级

永远先读入上下文。分三个层级：

层级 位置 作用
全局 ~/.claude/CLAUDE.md 对所有项目生效，个人通用规则
项目级 项目根目录 CLAUDE.md 技术架构、开发规范，可提交 Git
文件夹级 子文件夹中 仅对该文件夹生效

创建方式：

  • /init：cc 自动扫描项目生成项目级 CLAUDE.md
  • /memory：编辑全局 CLAUDE.md

最佳实践：CLAUDE.md 写最顶层基本不变的原则。项目级 CLAUDE.md 应动态更新——加了功能、踩了坑就同步更新，积累的错误经验越多，犯错越少。

7.2 Auto Memory——cc 的自动笔记本

第二层记忆。没写进 CLAUDE.md 的习惯、错误、经验，被后台 Agent 默默记录。

用 /memory 开启。它会记录四种类型：

类型 记录内容
user 关于你（角色、偏好）
feedback 你的反馈（”不要这样做”、”对，就这样”）
project 项目相关（进度、决策、技术选型）
reference 外部资源索引

如果记得不对，直接说「忘掉 XX」即可删除。

与 CLAUDE.md 的分工：CLAUDE.md 是你主动立的规矩（全部注入上下文），Auto Memory 是 cc 自己记录的笔记（按需读取），两者配合效果最佳。

7.3 自建参考文档

第三层。把不同功能的规范拆成独立文档，在 CLAUDE.md 中指定 cc 什么时候去参考。比如：

  • 建一个「品牌视觉规范」→ 修改 UI 时参考
  • 建一个「文案风格指南」→ 写产品文案时参考

八、六大高级扩展

如果只把 cc 当聊天助手，掌握前七章就够了。但如果你想把它变成真正的工作系统，这一章是关键。

8.1 Skill——技能包

把专业知识或操作流程变成按需调用的「外接大脑」。

安装：放进对应 skills 文件夹（全局 ~/.claude/skills/ 或项目 .claude/skills/）。

调用：两种方式——大模型主动调用，或 /skill 名称 直接调用。

找 Skill：用 find-skill 这个 skill 帮你搜索安装最合适的。

创建 Skill：用 Anthropic 出品的 skill creator，跟 cc 描述你想要的技能即可生成。

8.2 MCP——连接外部服务

MCP 是 AI 与外部工具的「转接头」——让 cc 读取 Notion 资料、查看 Figma 设计稿、访问数据库。

⚠️ MCP 占用 token 较多，不适合同时连太多服务。轻量场景转向 Skill，重量场景转向 CLI。

8.3 CLI 工具——当前最大趋势

CLI（命令行工具）原本是给程序员用的，但 AI 非常擅长用。比起模拟人类操作浏览器截图点击，输出命令要精准高效得多。

常见 CLI 工具：

  • 飞书 CLI：创建文档、写多维表格、发邮件、建日历
  • OpenCLI：将常用网页和社交媒体接口封装成 CLI

直接把地址粘贴给 cc，让它帮忙装好即可使用。

8.4 SubAgent——派出分身

需要并行处理或不想污染主上下文时使用：

  • 自动派生：任务复杂可并行时（如调研），cc 自动派生子 Agent
  • 手动创建：/agent 进入创建流程

子 Agent 有独立的上下文空间，可并行工作，结果汇总给主 Agent。主 Agent 也会自行决定把活派给哪个子 Agent。

8.5 Hook——条件反射

设定好「当 cc 怎么样时，自动执行什么」。示例：

  • 每次完成任务后自动发出提示音
  • 每次提交代码前自动触发格式检查

8.6 插件——全家桶

把 Skill、SubAgent、Hook、MCP 打包在一起。输入 /plugin 进入管理界面，可以 Discover（发现）和 Installed（已安装）。

总结

从零到一掌握 Claude Code，可以概括为四步：

关卡 核心内容
上手 安装、CC Switch 配模型、权限模式、基本交互、第一个项目
掌控 回滚、Git 后悔药、上下文管理
个性化 CLAUDE.md + Auto Memory + 自建文档，让它记住你和它的错误
高级扩展 Skill、MCP、CLI、SubAgent、Hook、插件

Claude Code 的能力边界还在不断扩展。但不必追逐所有新功能——把这些反复用在工作中，今年都很够用。

最重要的是，你在习惯一种新的协作方式：从一问一答，到构建系统、组织 AI 让它自己去干。习惯了这种模式，未来无论出现什么新工具，你都能快速上手。
