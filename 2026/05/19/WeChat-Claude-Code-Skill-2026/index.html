在微信里直接调用 Claude Code：一个开源 Skill 的实现全记录

发表于 2026-05-19 更新于 2026-08-30 分类于 AI技术

一、从 ClawBot 说起

腾讯最近开放了 ClawBot 插件——@tencent-weixin/openclaw-weixin。官方的意思是让大家把 OpenClaw 接进来，在微信里用 AI。

但有开发者做了另一件事：让 Claude Code 直接读取这个包的源码，把微信协议层提取出来，接上自己的 Agent。

结果就是：手机微信发一条消息，本地 Claude Code 处理完，直接把结果发回微信。 不需要 OpenClaw Gateway，不需要公网 IP，不需要域名，本地跑一个 Node.js 进程就够了。

项目已开源：https://github.com/Wechat-ggGitHub/wechat-claude-code

二、用 Superpowers 结构化开发

整个过程用了一个叫 Superpowers 的框架。它是 GitHub 上一个给 Claude Code 用的 Skill 框架，10 万 Star，热度很高。

Superpowers 的核心思路：不让 AI 随便写代码，而是按一套结构化的开发流程来——先头脑风暴想清楚，再写计划，最后并行开发。这次主要用了三个 Skill：

第一阶段：Brainstorming 头脑风暴

先让 Claude Code 去读 @tencent-weixin/openclaw-weixin 包的源码，分析协议层的每个细节：

  • 认证流程是怎样的
  • 消息格式长什么样
  • 长轮询的超时机制
  • 加解密的密钥怎么管理

讨论下来，方案基本确定：从包里提取微信协议层，把 OpenClaw 的消息处理逻辑替换掉，改成调用 Claude Agent SDK，用 query() 方法把消息发给 Claude Code，把流式返回的结果发回微信。

一个关键细节：整个过程中 Claude Code 不只是执行者，它会主动提出问题、挑战想法。 比如它问过：

  • 用基于 OpenClaw 的方案还是不基于 Gateway，自己做？
  • 要不要支持输入斜杠命令？
  • 如果涉及到授权，能不能用 yes/no 来控制？

这些问题帮助提前想清楚了很多边界情况。

第二阶段：Writing Plans 写实施计划

头脑风暴完了，方案清晰后，让 Claude Code 写了一份详细的实施计划，把整个项目拆成了十几个模块，每个模块都有具体的代码模板和接口定义。

哪些可以并行做、哪些必须串行，都标得清清楚楚。

计划包含的模块：

  • 微信协议层
  • 加解密处理
  • 媒体文件处理
  • 会话管理
  • 命令路由
  • 权限审批

第三阶段：Dispatching Parallel Agents 并行开发

这一步是整个流程里最爽的。Claude Code 同时派出多个 Agent，各自负责不同的模块。微信协议层、Claude SDK 对接、会话管理、命令路由——这些没有依赖关系的模块全部同时开工。

Agent 之间通过共享的接口定义协作，不用等一个写完另一个才能开始。

最终 15 个模块全部编译通过。

三、实际效果

第一次使用会弹出一个二维码，微信扫描后完成绑定。之后：

不需要公网 IP，不需要域名，本地电脑跑着就行。macOS 上用 launchd 管理守护进程，开机自动启动。

你可以在地铁上用手机给 Claude Code 派个活，等到了公司，活已经干完了。

四、这件事的意义

微信开放 ClawBot 插件，官方的意思是让大家把 OpenClaw 接进来。但底层协议是可以被读取的，这意味着：

微信 AI 的入口不只有 OpenClaw 一条路，任何 Agent 照着写对接层都能进。

如果你也想自己搭一套，整个流程可以直接用 Claude Code 口喷完成，需要做的只有审核和批准。

这背后更值得关注的是 Superpowers 这类 Skill 框架的价值——它把 AI 辅助编程从”随便写代码”升级为”结构化工程开发”：先充分讨论、再制定计划、最后并行执行。当 AI 能主动提问、拆解模块、协同多个 Agent 并行开发时，开发效率的提升是指数级的。
