Google Antigravity 汉化与美化实战：chuanban 主题补丁安装全记录（Windows 篇）

发表于 2026-11-21 更新于 2026-11-22 分类于 效率工具

一、前言

Google 借 Gemini 3 的东风推出了 agentic IDE「Antigravity」（社区戏称「反重力」），上手体验确实惊艳，但对国内用户来说有两道门槛：

  1. 网络门槛：登录和模型调用需要代理；
  2. 界面门槛：客户端目前只有英文界面，且默认字体对中文显示不友好。

第一道门槛网上教程很多（比如 X 上@alice_showmore 的《小白从 0—1 上手 Antigravity》，我就是照着这个入的门）。本文解决第二道门槛：用社区的 chuanban-antigravity-theme-patch 补丁，把 Antigravity 变成全中文界面 + 暖纸/深夜双主题 + 四层中西文字体排版 + Token 实时指标胶囊，并且全程不改客户端文件、可一键回滚卸载。

以下全部步骤在 Windows 10 + Antigravity 2.34.0 + 补丁 v5.5.3 上实测通过，踩的坑一并记录。

二、这个补丁的原理：为什么不碰安装目录？

先说清楚它为什么安全。chuanban 补丁走的是 CDP（Chrome DevTools Protocol）运行时注入路线：

它不修改 app.asar、不破坏签名、零第三方 npm 依赖。样式、1,940 条汉化词条、指标胶囊全部是运行时叠加的——关掉守护进程，客户端立刻还原官方原貌。这也是它支持 rollback / uninstall / --safe-mode 排障的底气。

注意：快捷方式被追加 --remote-debugging-port=0 参数是补丁的正常机制，不要手贱把参数删了，否则守护进程无法注入。

三、安装前置

依赖 要求 说明
Antigravity 客户端 2.34.0+（2.33.0+ 亦可） 官网下载安装即可
Node.js ≥ 22.13.0（推荐） 本机 v24 实测，功能全量启用
网络 能访问 GitHub + Google Drive 字体资源在 Drive 上
磁盘 ~200 MB 字体包 170 MB + 运行态若干

五、Step 2：下载字体（踩坑重灾区）

补丁需要的字体：AnthropicSerif-Regular/Bold.ttf、AnthropicMono-Regular.ttf，以及更纱黑体中文包。Windows 强烈推荐用作者打包好的拆分版 zip（170 MB，含 14 个 SC 字重 TTF），千万别下 791 MB 的 Sarasa-SuperTTC.ttc 整包——DirectWrite/Chromium 加载超大 TTC 会卡顿数秒（仓库 issue #19 有详细分析）。

坑 1：Python requests 的 TLS 会被代理掐断

我最先想用 gdown 下载 Drive 资源，结果报 SSLZeroReturnError——Clash 对不同客户端的 TLS 指纹处理不一致，curl 能通的代理，python requests 握手直接被 EOF。结论：代理环境下下载一律用 curl，别折腾 python 下载器。

坑 2：Drive 文件 ID 要自己解析

资源包是个公开文件夹，先抓目录页把文件名和文件 ID 配对：

需要的四个文件与 ID（2026-11 实测，v1.0.43 拆分包）：

坑 3：大文件下载要用 usercontent 域 + confirm 参数

用这个端点加 confirm=t 可以跳过病毒扫描提示页，170 MB 的 zip 两分钟就能拉完。下载完建议校验一下 TTF 文件头是 00 01 00 00（TrueType 签名），防止下到 HTML 错误页。

六、Step 3：注册字体

再跑一次 doctor，看到 "allRequiredInstalled": true 即通过。

关键细节：Windows 下单纯把 TTF 拖进字体文件夹不会写注册表，Chromium 的 local() 找不到字体。必须走 install-fonts 写入 HKCU\...\Fonts 并广播消息，这是仓库 README 反复强调的点。

七、Step 4：安装内核与守护进程

这一步会：部署 theme-patch/ 运行态目录 → 注册 AntigravityThemeDaemon 计划任务（开机自启）→ 幂等地给桌面/开始菜单等 5 处快捷方式追加 CDP 参数。输出里 serviceInfo.runningNow: true 表示守护进程已在工作。

安全软件提示：计划任务注册涉及 schtasks / wscript.exe，火绒、360 等可能弹窗拦截。选择放行即可；被拦了也可以按仓库 README 的 PowerShell 备选命令手动注册。

八、Step 5：启动与验收

坑 4：relaunch 是两阶段操作，中途别杀

让带调试参数的客户端跑起来的标准姿势：

它会先平滑关闭当前实例，再重新拉起（对 Antigravity 2.33.0+ 的冷启动做端口接力）。我就是在这里踩坑：relaunch 跑了三分多钟没输出，我以为卡死了把它杀掉——结果正好死在「旧实例已关、新实例未起」的中间态，留下一个诡异的残状态：DevToolsActivePort 文件在、但进程没了、CDP 端口无响应。

正确处理：要么让 relaunch 自己跑完（第一次冷启动最多等 12 秒接力）；要么中断后直接双击打过补丁的快捷方式启动，效果一样。

我本机的验收结果（节选）：

肉眼验真三特征（防止被 2.33.0 原生字体的视觉假象骗到）：

  1. 对话正文是 Anthropic Serif 衬线体（未注入时是无衬线）；

  3. 输入框底栏有实时指标胶囊，全界面中文。

九、安装后的个性化定制

所有定制只在 user/ 层改，保存后 2.5 秒热重载，不碰 core/：

user/config.json — 预设与模块开关：

user/i18n.override.json — 覆盖/新增词条：{"英文原词": "你的中文"}，即时生效。
user/custom.css / custom.js — 自定义样式与前端钩子。

把 enabled 设为 false 可在 2.5 秒内无损卸载全部注入，还原英文原貌。

十、日常维护速查

客户端热更新之后如果汉化失效，先跑 doctor 看 cdpStatus——大多数情况是快捷方式参数被更新程序重置了，补丁内置的「Windows 快捷方式自愈」会自动处理，等一次重启就好。

十二、结语

整个流程走下来，最深的感受是这套补丁的工程素养：SHA-256 内核校验、core/user 分层、热重载、safe-mode 定界、一键回滚——把「魔改客户端」做成了可审计、可回退的标准软件分发。对想上手 Antigravity 又被英文界面劝退的朋友，照着本文 Step 1 → Step 5 走一遍，半小时内可以搞定。
