Omarchy 接入 Tailscale:从一键安装到 Windows/Mac 互通的远程开发全记录

发表于 2026-11-23 分类于 Linux

前情提要:在 Apple Silicon Mac 上无痛试装 Omarchy 里,Omarchy 跑在 Try Omarchy 虚拟机中,远程访问走的是「Windows → Tailscale → Mac → socat 中继 → QEMU 端口转发 → 客机」这条长链路。能用,但每加一个服务就要多配一段转发。

这次的思路很简单:把 Tailscale 直接装进 Omarchy,让虚拟机自己成为 tailnet 里的一台设备。链路变成:

不需要 socat,不需要端口转发,任何端口只要防火墙放行就能直接访问。

一、先说结论:最终状态

项目 状态
Omarchy 加入 tailnet ✅ 独立设备,拿到自己的 100.x.x.x
设备名 ✅ 从自动生成的 xxx-1 改为好记的名字
密钥过期 ✅ 已关闭,不会 180 天后掉线
防火墙 ✅ ufw 只对 tailscale0 网卡放行 SSH(22)
Windows → Omarchy ✅ VS Code Remote-SSH / PowerShell / PuTTY 免密登录,直连约 13 ms
Omarchy → Mac ✅ 免密 SSH,局域网直连约 5~16 ms
Taildrop 收文件 ✅ 自动存到 ~/Downloads

文中设备名统一用占位符:

占位符 含义
omarchy-vm Omarchy 虚拟机(Linux,aarch64)
my-win 学校的 Windows 电脑
my-mac 跑虚拟机的 MacBook Air
<user> / <mac-user> Omarchy / Mac 的登录用户名
100.a.b.c 等 各设备的 tailnet IP
tailXXXX.ts.net tailnet 的 MagicDNS 域名后缀

三、设备管理:改名 + 关闭密钥过期

3.1 坑二:设备名自动变成 xxx-1

tailscale status 看到本机叫 xxx-1。原因是 tailnet 里已经有一台同名设备:我的 Windows 主机名和 Omarchy 的主机名一样,Tailscale 自动给后加入的设备加了 -1 后缀。

  1. 管理后台(推荐):Machines → 设备右侧 ... → Edit machine name → 关掉 Auto-generate from OS hostname → 输入新名字 → Update name;
  2. 命令行(已设 operator 时无需 sudo):

名字只能用小写字母、数字和 -。改完几秒内全网生效,MagicDNS 会解析新名字:

注意:旧名字立刻失效,所有用名字访问的地方(SSH 配置里的 HostName、书签)都要更新;用 IP 写的配置不受影响。

3.2 关闭密钥过期(常驻设备必做)

Tailscale 默认每 180 天要求设备重新登录。对一台放在家里、靠远程访问的机器来说,这意味着某天在学校突然连不上,而且没法远程修复。

在管理后台对应设备的 ... 菜单里选 Disable key expiry。验证:

手机、笔记本这种随身设备可以保留默认的过期策略,丢了也安全。

四、防火墙:ufw 只对 tailscale0 放行

4.1 坑三:Tailscale 通了,SSH 却连不上

装好 Tailscale 后,tailscale ping 一切正常,但从 Windows ssh 就是超时。看一眼 ufw 规则(/etc/ufw/user.rules 普通用户可读):

Omarchy 默认 ufw default deny incoming,22 和 5900 端口只对 10.0.2.2(Try Omarchy 的 slirp 网关,也就是 Mac)放行。从 tailscale0 网卡进来的连接全部被丢弃。

4.2 只给 tailscale0 开口子

这条规则只匹配从 tailscale0 进来的流量,局域网和公网仍然被挡。也就是说只有自己 tailnet 里的设备能 SSH 进来,不需要把 22 端口暴露出去。

5.4 VS Code Remote-SSH:真正的生产力

  1. 安装 Remote - SSH 扩展;
  2. F1 → Remote-SSH: Connect to Host… → 选 omarchy-vm;
  3. 远程平台选 Linux,首次连接 VS Code 会在 Omarchy 上自动安装服务端(~/.vscode-server),走中继时可能要一两分钟;

连上之后:

  • File → Open Folder 打开的是 Omarchy 上的目录;
  • Ctrl+` 打开的终端跑在 Omarchy 上;
  • Python、Jupyter 等扩展需要在扩展页点 Install in SSH: omarchy-vm 再装一次;
  • Omarchy 上起的 Web 服务(如 Jupyter 8888),VS Code 会自动端口转发到 Windows 的 localhost;
  • 长时间任务放进 tmux new -s sim,VS Code 断开也不影响,重连后 tmux attach -t sim。

5.5 PuTTY(可选)

PuTTY 不读 OpenSSH 的配置文件,也不认 OpenSSH 格式的私钥,需要单独设置:

  1. 打开 PuTTYgen → Load → 文件类型改为 All Files → 选 id_ed25519(不是 .pub)→ Save private key 存成 id_ed25519.ppk;
  2. PuTTY → Session:Host Name 填 <user>@100.a.b.c,Port 22;
  3. Connection → SSH → Auth → Credentials:选上一步的 .ppk;
  4. Connection:Seconds between keepalives 填 30;
  5. 回到 Session,在 Saved Sessions 输入名字 → Save,以后双击即连。

三种方式连的是同一台机器:写代码用 VS Code,只要终端用 PowerShell 的 ssh omarchy-vm 最省事,PuTTY 胜在会话管理直观。

七、DERP 中继 vs 直连:延迟实测

装好后用 tailscale ping 看各设备的连接路径:

via DERP(...) 表示没打通直连,流量绕到了 Tailscale 的中继服务器。Tailscale 在国内没有官方 DERP 节点,tailscale netcheck 显示最近的是香港,但实际分配到的经常是欧美节点,延迟三四百毫秒,SSH 敲字都能感觉到。

有意思的是,Windows 第一次 SSH 连上后,再 ping 一次:

Tailscale 会在后台持续尝试 NAT 打洞,有流量之后很快就切到了直连,从 350 ms 降到 13 ms。即使 Omarchy 躲在 QEMU slirp NAT 后面(外面还有 Mac、路由器两层 NAT),也能打通。

如果长期打不通直连,可以按顺序尝试:

  1. Windows 防火墙放行 Tailscale,路由器开启 UPnP;
  2. 让一台网络条件好的设备当 Peer Relay;
  3. 有国内云服务器的话,自建 DERP 节点,写进管理后台的 Access Controls(ACL)配置,延迟能降到几十毫秒。

八、Tailscale 日常用法速查

场景 命令 / 做法
查看所有设备与连接状态 tailscale status
检查是直连还是中继 tailscale ping <设备名>
网络诊断 tailscale netcheck
发文件给其他设备 tailscale file cp 文件 my-mac:
接收文件 Omarchy 已自动存到 ~/Downloads;其他设备从系统「分享」菜单选 Tailscale
只在 tailnet 内发布 Web 服务(自动 HTTPS) tailscale serve --bg 8888 → https://omarchy-vm.tailXXXX.ts.net
临时公开到公网 tailscale funnel 8888,用完立刻 tailscale funnel reset,别暴露 Jupyter/SSH
用 Tailscale 账号做 SSH 认证 tailscale set --ssh
共享整个局域网 tailscale set --advertise-routes=192.168.x.0/24,后台批准
当出口节点 tailscale set --advertise-exit-node,后台批准

安全上的几条习惯:

  • 不用的旧设备在管理后台及时删除;
  • 防火墙规则按网卡收紧(in on tailscale0),不要图省事 ufw allow 22;
  • 不再需要的免密登录,删掉对方 authorized_keys 里对应那一行即可撤销;
  • tailnet 里加入他人设备时,用 ACL 限制可访问的端口。

九、附:Omarchy 关窗口

折腾过程中弹了好几个终端窗口,顺手记一下:Omarchy 关闭当前窗口是 Super + W(Super + Q 也行);浏览器标签页是 Ctrl + W。查快捷键可以用 hyprctl binds,或者 Super + K。

十、经验总结

  1. 优先用发行版自带的安装命令:omarchy-install-service-tailscale 一条命令包含安装、自启、operator、Taildrop、顶栏插件,比官方 curl | sh 完整;
  2. 半截安装要逐项核对:脚本没有 set -e 时,中间一步失败不会中断,要看日志确认每一步都成功了;
  3. 网络通 ≠ 服务通:tailscale ping 能通只说明隧道正常,端口能不能进还要看本机防火墙;
  4. 防火墙按网卡放行:ufw allow in on tailscale0 既解决问题又不扩大暴露面;
  5. 常驻设备关闭密钥过期:否则半年后在外面突然失联;
  6. SSH 配置写 IP + 保活:改名、中继抖动都不怕;
  7. 中继慢先等等:有流量后 Tailscale 会自己打洞,13 ms 的直连比 350 ms 的中继舒服太多。

至此,Omarchy 从「Mac 上的一个窗口」变成了 tailnet 里一台真正的开发机:在学校打开 VS Code,点一下就进到家里的 Linux 环境。
